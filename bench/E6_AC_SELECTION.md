# E6-A vs E6-C：工程上线价值对比（推荐：A）

- 日期：2026-10-11 · 依据：首轮实验（`EXPERIMENT_ROUND1.md`）+ 组合实验 + 裁判层（`judge/JUDGE_REPORT.md`）
- 事实前提：**58 集上 A 与 C 指标完全等效**（入选 95.7↔95.7、SHR 100↔100、零回归、@5/@10 不动）；裁判层验证的是 A（C 因与 A 等效推断同结论，审计未单独覆盖 C——局限见文末）。

## 五维对比

| 维度 | A（密度序：`score/len` 装入序） | C（两阶段：topN 限长保底 → 余量填充） |
|---|---|---|
| **1. 代码复杂度** | 最小：仅改装入排序键（1 个表达式，无新参数） | 中：新增阶段结构 + 2 个参数（`phase1_n=5`、`phase1_fraction=0.6`）+ 每块限长逻辑 |
| **2. 参数可解释性** | 优：单一公式"单位 token 信息价值"，无需调参 | 中：两参数有直观语义，但存在交互（N 与 fraction 需联合调） |
| **3. 未来数据规模扩展** | 优：无阶段假设，对块长/分数分布变化自适应 | 中：`top5` 是固定假设——数据规模、块粒度或语言风格变化时需复调参数才不失配 |
| **4. 长文档风险** | 中：密度序自然降权长块，长答案块的截断"按需发生"（最后装入者被截） | 中：对 top5 每块的硬限长（2160 字符）可能**集中切掉答案所在的后半段**；风险更尖锐 |
| **5. token 利用率** | 高：15864/18000 ≈ **88%**（预算基本装满） | 中：15121/18000 ≈ **84%**（平均 ~2.9K 未用；由 phase1 硬配额 + phase2 装不满所致） |

## 推荐：**E6-A（density）**

理由（按权重）：
1. 零新参数、代码面最小——对开源项目意味着更小的审查/回归成本（用户核心诉求：可追溯、可撤回）。
2. 与数据规模解耦——系统面向企业不同语料（当前 223 资产，未来更大），不引入"topN 假设"负债。
3. 预算利用更满（88% vs 84%），等效效果下不浪费上下文空间。
4. C 的"显式两阶段保障"在语义上有吸引力，但在本案中未转化为任何可测收益；其价值应在 A 上线后、扩集复验中若发现"结构保障"缺口再启用（保留为设计备选、归档不删）。

## 上线形态（待用户批准后执行）

- 生产实现为 **opt-in 配置**：`context.budget_policy: score|density`（默认 `score`=现状，行为零变化）；
- 单提交、附 diff 与一键回滚说明；先在 daemon 热态下 A/B 复测一轮再考虑默认切换。
- 风险提示（保持诚实）：截断行为变更已由裁判层验证"无质量伤害"（58 集），但**长文档切片在扩集（Step 4 的 50 条）中需复验**后再全面切换默认。

## 局限

- 审计覆盖 A 未覆盖 C（假设同构）；扩集后建议对 A/C 各跑一轮裁判抽查。
- LLM Context Precision 判定不可靠（见审计笔记），本对比未依赖该指标。
